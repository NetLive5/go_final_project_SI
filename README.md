# Планировщик задач

Веб-сервер на Go для TODO-листа. Задачи хранятся в SQLite, могут иметь даты выполнения и правила повторения. Сервер раздаёт фронтенд из `web` и предоставляет API для создания, просмотра, редактирования, удаления и выполнения задач. Поддерживаются поиск по заголовку и комментарию, а также фильтр по дате. При заданном `TODO_PASSWORD` операции с задачами требуют JWT-аутентификацию.

Запустить проект можно локально или в Docker — выберите подходящий способ.

## Выполненные задания со звёздочкой

- Повторение задач по дням недели (`w`) и дням/месяцам (`m`), включая последний и предпоследний дни месяца.
- Поиск задач по тексту и дате.
- Настройка порта (`TODO_PORT`) и пути к SQLite-файлу (`TODO_DBFILE`) через окружение.
- Вход по паролю из `TODO_PASSWORD` с JWT-токеном.
- Сборка и запуск Docker-образа.

## Локальный запуск

Из корня проекта запустите сервер:

```sh
cp .env.example .env
go run .
```

При старте сервер автоматически загружает `.env`, если файл существует. Можно сразу выполнить `go run .` и без него: по умолчанию сервер слушает порт `7540`, а база `scheduler.db` создаётся в текущей директории. Откройте <http://localhost:7540/>.

В шаблоне `.env.example` задан пароль `Пароль`; замените его на свой или удалите строку `TODO_PASSWORD`, чтобы отключить аутентификацию. Переменные окружения, уже заданные в shell, имеют приоритет. `TODO_PORT` и `TODO_DBFILE` необязательны; значения по умолчанию — `7540` и `scheduler.db`.

## Тестирование

Тесты обращаются к работающему серверу. Запустите его в одном терминале, затем из корня проекта в другом выполните:

```sh
go test ./tests
```

В `tests/settings.go` установлены параметры:

```go
var Port = 7540
var DBFile = "../scheduler.db"
var FullNextDate = true
var Search = true
var Token = "" 
```

`FullNextDate` включает проверки правил `w` и `m`, `Search` — проверки текстового и календарного поиска. Перед запуском тестов `TestMain` загружает корневой `.env` и получает JWT через `/api/signin`, если задан `TODO_PASSWORD`. Ошибка входа останавливает прогон с понятным сообщением. Если пароль задан только в shell, запустите тесты с той же переменной `TODO_PASSWORD`; готовый токен можно передать через `TODO_TOKEN` или записать в `Token`. Тест `TestTasks` очищает таблицу `scheduler` перед проверкой.

## Docker

Соберите образ с Docker ID и тегом `v1`:

```sh
docker build -t netlive1/go-final-project:v1 .
```

Запустите контейнер из корня проекта. Каталог проекта монтируется в `/data`, поэтому база `/data/scheduler.db` в контейнере хранится как `scheduler.db` в проекте на хосте. Для передачи настроек из `.env` используйте `--env-file`:

```sh
docker run --rm -p 7540:7540 -v "$PWD:/data" --env-file .env netlive1/go-final-project:v1
```

Переменные из `.env` передаются контейнеру при запуске, поэтому менять их можно без пересборки образа. Для Docker оставьте `TODO_DBFILE` не заданной: образ сам использует `/data/scheduler.db`. Не добавляйте `.env` в Git.

Откройте <http://localhost:7540/>. Если порт `7540` на хосте занят, замените проброс на `-p 7541:7540` и перейдите по адресу <http://localhost:7541/>. Если меняете `TODO_PORT` внутри контейнера, укажите этот порт справа в `-p`, например `-p 7540:8080` для `TODO_PORT=8080`.
